正在精读论文关键段落，核对数字与机制后只返回 Library 读卡正文。# SmartGen: Seamless Disaggregated LLM Inference with Selective KV Cache Transfer

> P/D 分离下全量 KV 层间传输在 25 Gbps 云实例上撑爆带宽 → 按位置重要性预推、解码时本地/远程双通道并行拉取、注意力空闲期投机补传 → TTST 最高降 4.3×，后续 TBT 贴近全量本地。

## Essence

**问题：** Prefill/Decoding 拆到不同节点后，长上下文 KV cache 必须跨机搬。在 25 Gbps L20 云实例上，48K tokens 的全量传输耗时可达 prefill 计算的 6.5×，层间 overlap 盖不住，形成 stage-transition stall，TTST 被拖垮。

**做法：** 不是“传更少就算了”，而是把 KV 分成三级并配三条路径——(1) **profile-based proactive**：离线 profiling 抓跨请求稳定的位置重要性，prefill 期间用 RDMA WRITE 只预推 top-$K_r$ 块；(2) **parallel on-demand**：解码时用 KV mask 把 index 拆成 local/remote 两路，本地 H2D 与远程 GDR 拉取并行，去掉关键路径上的网络 RTT；(3) **speculative**：注意力计算期间 NIC/CPU 空闲，按重要性每次补传约 10% 剩余块，约 10 步后本地齐全。

**证据：** 相对 full transfer，GovReport + Qwen3-14B 上 TTST 最高降 **4.3×**；TBT 接近全量已在本地的理想情形；LongBench 相对 full-cache 准确率约 96%–120%。

**边界：** 场景锚定低带宽自托管云（约 15–32 Gbps RDMA）；依赖动态 KV selection（InfiniGen/HATA）与（理想路径上的）GDR；输出长度评估固定 64 tokens，勿当成任意长生成的端到端 SLA 证明。

## Claims

1. 在有限云带宽下，层间 overlap 无法隐藏全量 KV 传输：48K tokens 时传输约为 prefill 的 6.5×；带宽限到 15 Gbps 时差距可放大到 7.1× [§3.1, Fig. 2]。
2. 多 prefill、少 decoding 的资源配比使 KV 向单 decoding 节点汇聚，进一步饱和 decoding 侧网卡 [§3.1]。
3. 重要 KV 在跨数据集、4K–16K prompt 长度下呈现稳定的**位置分布**（positional similarity），可用校准集离线近似在线重要性 [§4.1, Fig. 5]。
4. Prefill 阶段 SOTA 稀疏注意力依赖 decoding query/hidden states，无法在 prefill 直接做精确选择——因此需要 profile 近似 + 解码侧补全 [§3.2, Challenge 1]。
5. 即便 prefill 预传一半 KV，仍约有 34% 需 on-demand；且 fine-grained 动态选择每步都会产生新缺失，仅靠 reuse 仍可使 TBT 持续约 1.1× [§3.2, Fig. 3]。
6. 将 KV 条目分为 universally important / context-dependent / less important，并分别走 proactive、parallel on-demand、speculative 三条路径，可同时压 TTST 与后续 TBT [§4, Fig. 4]。
7. Profile-based 策略相对 random/sequential 可将 on-demand ratio 最高降约 51%/38%，TBT 相对最优策略接近 [§5.3, Fig. 15]。
8. Parallel on-demand 通过 index 拆分与重排，把远程 RTT 从“本地加载 → 再等远程”的串行关键路径中移出，TBT 降约 1.1×（L20）/1.2×（V100S）[§5.3, Fig. 13]。
9. Speculative transfer（默认 speculative ratio 10%）约 10 个 decoding 迭代内补齐剩余 KV，之后 TBT 对齐理想本地；ratio 20% 会干扰前几 token（TBT 最高 +1.4×）[§4.3, §5.3, Fig. 14]。
10. 相对 full transfer，SmartGen 在 GovReport 上 TTST 最高降 4.3×；batch=6、MultiFieldQA、Qwen3-14B 上约 3.7× [§5.2, Fig. 9–11]。
11. 带宽越低收益越大：TTST 优势从 32 Gbps 的约 2.5× 增至 15 Gbps 的约 3.3×；但 15 Gbps 时 TTST 仍高于“理想”（前两层全量 + selection metadata 占满带宽）[§5.2, Fig. 12]。
12. 准确率由所接 KV selection 决定：SmartGen+InfiniGen/HATA 相对 full-cache 约 96%–120%；同设置下 HACK（2-bit 同态量化）约 13%–77% [§5.2 Fig. 9 表, §5.5 Fig. 17]。
13. 设计与具体 selection 算法解耦：统一 KV index 抽象下同时验证 training-free（InfiniGen）与 training-based（HATA）[§4.4, §5.1]。

## Assumptions

- Prefix cache hit ratio 取 75%，作为文献 60%–90% 区间的代表值 [§3, §5.1]。
- 4K–16K 上的位置重要性分布可推广到评估中更高的 batched token 规模（最高约 60K–96K）[§4.1 vs §5]。
- 前两层 attention 的 KV 始终重要且必须全选/全传 [§4.1, Eq. 1]。
- RDMA 有序交付保证 “先 WRITE KV 块、再 WRITE mask” 的门铃批处理语义正确 [§4.2]。
- Attention 结果对序列维上已选 KV 的排列顺序不敏感（因位置信息已在 cache 内），故可对 remote 条目重排以利 scatter [§4.2]。
- 评估请求输出长度固定 64 tokens；TBT 统计排除 TTST [§5.1]。
- KV selection 默认最大 selection ratio 20%（及 InfiniGen/HATA 建议超参）[§5.1]。

## Method

**Before vs After：**

| | Full transfer | SmartGen |
|--|---------------|----------|
| Prefill→Decode 传什么 | 每层全量 KV | 仅 top-$K_r$ 重要块 + 后续按需/投机补齐 |
| 解码侧缺失 | 理论上无 | mask=2 的条目走远程 lane |
| 关键路径上的网络 | 主要卡在 stage 切换（TTST） | 尽量不出现在逐步 attention 前 |

**输入：** Prefill 产出的 per-layer KV（先 offload 到 host）、KV selection 算法给出的 $BH\times k$ index、离线重要性矩阵 $I_{l,m}$。

**核心步骤：**

1. **离线 profiling：** 在校准集（2WikiMultihopQA，与评测分离）上跑推理，统计每 entry 被选频次；沿序列维切 $M{=}1$K 的 block，得 $I_{l,m}$（$l\in\{0,1\}$ 置 $\infty$ 强制全选）[Eq. 1]。
2. **定预传量 $K_r$：** 用 profile 的 prefill 时间 $T_p$ 与全量传输时间 $T_t$：
   $$K_r = L\cdot M\cdot\frac{L-1}{L}\cdot\frac{T_p}{T_t}$$
   再 clip 到 $[2M, LM]$，使前两层总能进预算 [Eq. 2]。负载低时公式可回退接近全量。
3. **Proactive path：** 每层 KV offload 后，若 block 属 top-$K_r$，则 RDMA WRITE 推到 decoding 的 KV pool，并门铃批处理更新 int8 KV mask（$B\times N$：0=pad, 1=local, 2=remote）。
4. **Parallel on-demand：** Algorithm 1 用 mask 把 selected index 拆成 local/remote；可选按 mask 降序重排使 remote 连续，便于 NIC scatter 直写 GPU 正确行。本地 H2D 与远程 SEND index→RECV entries 并行；两边齐了再做 attention。
5. **Speculative path：** 每层 attention 开始时通知 prefill 网络空闲；按 $I_{l,m}$ 顺序 WRITE 剩余块，每次约总块数的 10%，约 10 步补齐且尽量不抢 on-demand。

**输出：** Decoding GPU 上 assembles 好的 selected KV，供稀疏 attention；长期则趋向全量本地。

**非理想硬件：** 无 GDR 时改为 host 侧 mask/拆 index，远程先落 host 再 H2D（论文称 PCIe≫网络，可接受）[§4.4]。

## Eval

- **硬件：** 3× ecs.gn8is-2x.8xlarge prefill（2×L20/节点，32 Gbps）+ 1× ecs.gn8is.4xlarge decoding（1×L20，25 Gbps）；另测 15 Gbps 更小实例与 CloudLab V100S 物理机 [Table 1, §5.1–5.3]。
- **模型：** Qwen3-8B/14B、Llama-3.1-8B、Gemma-3-12B、Phi-4-14B。
- **数据：** LongBench 四任务子集 MultiFieldQA / GovReport / SAMSum / LCC（均长约 7K/10K/9K/3K）；校准用 2WikiMultihopQA；默认 batched 最高约 60K tokens。
- **基线：** Full transfer（层间全量）；Partial transfer（顺序前 $K_r$ 块 + 朴素 on-demand）；HACK（2-bit 同态量化 KV）。统一底层推理栈，FlashAttention/FlashInfer。
- **变体：** SmartGen+InfiniGen 与 SmartGen+HATA。
- **指标：** 用户侧 CTL；TTST；TBT（不含 TTST）；LongBench 任务指标及相对 full-cache 准确率。
- **消融：** 逐项叠加 profile / parallel / speculative；敏感性含序列长、block 数 $M$、selection ratio、带宽、batch size。

## Weaknesses

- **输出长度固定 64：** 无法观察长生成下 speculative 完成前后的稳态与尾延迟分布；“TBT 对齐理想”主要覆盖短续写 [§5.1]。
- **位置相似性外推未单独证明：** 热力图验证在 4K–16K，服务侧 batched 可到 60K–96K；grouped/periodic profiling 仅设计讨论，未进主实验 [§4.1, §4.4 vs §5]。
- **15 Gbps 下仍高于理想 TTST：** 前两层强制全传 + selection metadata 成为新瓶颈，作者标 future work，说明“选择性”未覆盖冷启动/元数据路径 [§5.2]。
- **与 HACK 的对比维度纠缠：** 一边是 ~20% 动态稀疏 + 全精度，一边是全量 2-bit 量化；准确率差距更多反映 sparsity vs quantization 对 LongBench 的敏感度，而非“传输引擎”单独胜负 [§5.2, §5.5]。
- **Partial 基线偏弱：** 顺序块 + 串行 on-demand 几乎是 strawman；缺“同样用 profile 选块但无 parallel/speculative”的完整交叉表时，三路径各自贡献依赖逐步叠加消融解读 [§5.3]。
- **复现与多租户现实：** eRDMA/GDR、门铃批处理、scatter 上限、与具体 serving 栈的集成细节未开源到可审计程度；多租户抢带宽、前缀缓存真实 hit 分布未建模（固定 75%）。
- **高带宽场景证据不足：** 明确对标低成本云；与 Mooncake 类 高带宽全量路径无同台对比，高带宽下是否退化为 full transfer 仅由公式推断 [§2.2, §4.4]。

## Relations

- **builds-on** InfiniGen [37] [high]：解码侧 selection/prefetch 与“前几层必保留”直接接入；SmartGen 把其 index 抽象接到传输平面而非改算法。
- **builds-on** HATA [24] [high]：作为 training-based selection 的第二实现，用来证明传输引擎与算法训练方式正交。
- **orthogonal** HACK [82] [high]：论文明确 sparsity 减流量 vs 量化减位宽正交，并讨论可组合；评估中作主要对比系统。
- **extends** Splitwise / DistServe 等 P/D 分离系统 [45, 85] [med]：继承 prefill–decode 拆分与层间 overlap 思路，但用 selective transfer 打低带宽 stage-transition stall。
- **competes-with** Mooncake [47] [med]：同属 KV-centric 分离架构；Mooncake 侧写高带宽 RDMA 全量路径，SmartGen 专攻租用云有限带宽下的选择性路径。
- **builds-on** StreamingLLM 等静态稀疏 [70] [med]：位置/窗口先验启发 proactive；实验显示 profile 在 full-attention 层上可进一步压 on-demand ratio。

## Takeaway

- **可抄的方法结构：** 传输问题拆成 “能静态预判的 / 必须动态补的 / 可后台慢慢搬的”，并分别设计路径与限流（$K_r$、speculative ratio），比单一 “压缩或量化” 更贴合 P/D 状态机。
- **要复查的点：** 位置 profiling 的长度外推、固定 64-token 输出、以及与量化基线纠缠的准确率叙事；低带宽下前两层+metadata 仍可能钉死 TTST。
- **若只记一句：** SmartGen 的关键不是“少传 KV”，而是让**阶段切换只搬位置上稳的重要块，解码每步网络不挡本地加载，空闲时再把剩下的搬完**。
