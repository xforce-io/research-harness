# SmartGen: Seamless Disaggregated LLM Inference with Selective KV Cache Transfer

> Prefill/Decoding 分离架构下 KV cache 全量传输撑爆云实例有限带宽 -> 仅按重要性分级选择性地预传、按需并行拉取、闲时投机补传 KV 条目 -> TTST 降低最高 4.3× 且精度无损。

## Essence

**问题：** P/D 分离推理中，长上下文（48K tokens）的全量 KV cache 传输耗时是 prefill 计算的 6.5×，在 25 Gbps 云网络下造成 "stage-transition stall"，TTST 严重恶化。

**做法：** 将 KV 条目分为三类——全局重要（prefill 阶段基于离线 profiling 的位置相似性提前推送）、上下文相关（decoding 阶段通过双通道并行按需拉取，网络传输与本地 KV 加载重叠）、不重要（decoding 注意力计算时空闲网络资源投机补传）。

**证据：** 在 Alibaba Cloud L20 实例上，SmartGen 相比全量传输将 TTST 降低最高 4.3×（GovReport, Qwen3-14B），同时 LongBench 准确率保持在 full-cache baseline 的 96%–120%。

**边界：** 依赖 RDMA 网络和离线 profiling 的位置相似性假设；profiling 在 4K–16K prompt 长度范围内验证，超出此范围的外推未经检验。

## Claims

1. 在 P/D 分离架构中，KV cache 全量传输无法被 prefill 计算有效隐藏：48K tokens 下传输耗时是 prefill 的 6.5×，在 15 Gbps 带宽下差距扩大至 7.1× [§3.1, Fig. 2]。
2. 重要 KV 条目在不同数据集和 prompt 长度下呈现一致的位置分布模式（positional similarity），使得离线 profiling 可用于预测在线请求的重要 KV 区域 [§4.1, Fig. 5]。
3. Profile-based proactive transfer 通过按重要性排序预传 KV 块，将 on-demand ratio 最高降低 51%，TBT 优化 1.1× [§5.3, Fig. 15]。
4. Parallel on-demand transfer 通过将 KV index 分割为本地/远程两条并行通道，将网络 round-trip 从关键路径移除，TBT 降低 1.1–1.2× [§5.3, Fig. 13]。
5. Speculative transfer 利用注意力计算期间空闲的 NIC 和 CPU 资源，在约 10 个 decoding 迭代内补传全部剩余 KV，之后 TBT 对齐理想情况 [§5.3, Fig. 14]。
6. SmartGen 在 LongBench 四个任务上准确率保持在 full-cache baseline 的 96%–120%，而 HACK（2-bit 量化）准确率仅为 13%–77% [§5.5, Fig. 17]。
7. SmartGen 的 TTST 优势随带宽降低而增大：从 32 Gbps 的 2.5× 到 15 Gbps 的 3.3× [§5.2, Fig. 12]。

## Assumptions

- Prefix cache hit ratio 为 75%，反映 60%–90% 报告范围的代表值 [§3]。
- 离线 profiling 得到的重要 KV 位置分布在 4K–16K 范围内对同模型的所有请求近似有效，prompt 长度变化不影响相对位置分布 [§4.1]。
- RDMA NIC 的 in-order delivery 保证 KV mask 更新在对应 KV block 写入后才生效 [§4.2]。
- RDMA NIC scatter-gather 上限（如 20）足以显著减少 I/O 次数（如 20×）[§4.2]。
- 输出长度固定为 64 tokens 用于评估 [§5.1]。

## Method

**Before（全量传输）:** Prefill 节点逐层将完整 KV cache 通过 RDMA 推送到 decoding 节点 -> 长上下文下传输时间远超 prefill 计算 -> TTST 恶化。

**After（SmartGen 三路径）:**

| 路径 | 触发阶段 | 机制 | 目标 |
|------|---------|------|------|
| Profile-based proactive | Prefill | 离线 profiling 生成重要性矩阵 $I_{l,m}$，选 top-$K_r$ 块用 RDMA WRITE 预推 | 消除 stage-transition stall |
| Parallel on-demand | Decoding | KV index 分割为 local/remote 两路，本地加载与远程 RPC 拉取并行 | 移除网络 round-trip 出关键路径 |
| Speculative | Decoding (空闲) | 注意力计算时 NIC 空闲，按重要性补传剩余 KV 块 | 逐步消除后续 on-demand 开销 |

**核心计算：**

1. **离线 profiling：** 对校准数据集跑推理，按 KV block（$M=1K$ tokens）统计每块被选中频率，生成重要性矩阵 $I_{l,m}$；前两层（$l=0,1$）强制全选。

2. **预传量计算：** $K_r = L \cdot M \cdot \frac{L-1}{L} \cdot \frac{T_p}{T_t}$，即总块数乘以可被 prefill 重叠的传输时间比例，clip 到 $[2M, LM]$。

3. **KV mask 机制：** decoding 节点维护 $B \times N$ 的 int8 mask（0=padding, 1=local, 2=remote）；prefill 节点通过 GDR RDMA WRITE 同步更新 mask，与 KV 块写入合并为单次 round-trip（doorbell batching）。

4. **Index splitting + reordering（Algorithm 1）：** 从 KV mask 中查出每个 selected index 的状态 -> 分割为 local_index / remote_index -> 按 mask 值降序排序使 remote 条目连续 -> RDMA NIC scatter 将远程条目直接写入 GPU memory 正确位置。

5. **Speculative transfer：** 每个注意力层开始时 decoding 节点通知 prefill 节点网络空闲；prefill 按重要性顺序发送剩余块，每次限制为总块数的 10%（speculative ratio），避免干扰 on-demand 传输。

**输出：** decoding 节点 GPU 上准备好 selected KV 条目供 attention 计算。

## Eval

- **数据集：** LongBench 四个任务子集——MultiFieldQA（7K avg）、GovReport（10K）、SAMSum（9K）、LCC（3K），batched tokens 最高 60K；2WikiMultihopQA 作为校准集（不用于评估）。
- **模型：** Qwen3-8B/14B、Llama-3.1-8B、Gemma-3-12B、Phi-4-14B。
- **硬件：** 3× ecs.gn8is-2x.8xlarge prefill（2× L20 each, 32 Gbps）+ 1× ecs.gn8is.4xlarge decoding（1× L20, 25 Gbps）；额外 V100S CloudLab 物理服务器验证。
- **Baselines：** Full transfer（逐层全量传输）、Partial transfer（顺序选前 $K_r$ 块 + on-demand）、HACK（2-bit 同态量化）。
- **Metrics：** CTL（累积 per-token 延迟）、TTST、TBT（排除 TTST）、LongBench 准确率指标。
- **KV 选择算法：** InfiniGen（training-free）和 HATA（training-based），selection ratio 默认 20%。
- **主要结果：** SmartGen 在 GovReport/Qwen3-14B 上 TTST 降低 4.3× vs full transfer；TBT 接近 full transfer 理想值；准确率 96%–120% relative。

## Weaknesses

- 所有评估的输出长度固定为 64 tokens，无法评估长文本生成场景下 speculative transfer 的累积效果和 on-demand ratio 随生成步数的变化。
- 离线 profiling 的位置相似性仅在 4K–16K prompt 范围验证，但实验使用高达 60K batched tokens（多请求拼接），profiling 对 batched 场景的适用性未单独分析。
- 前两层 KV cache 被强制全选并传输，在 15 Gbps 带宽下 SmartGen 的 TTST 超过理想情况，作者承认此开销但未提供解决方案 [§5.2]。
- 与 HACK 的对比可能不公平：SmartGen 使用 20% KV selection ratio（即仅用 20% KV 做注意力），而 HACK 保留全部 KV 但 2-bit 量化——两者优化维度不同，准确率差异更多反映 KV sparsity vs quantization 的本质差异而非传输方案优劣。
- 离线 profiling 的周期性更新和 grouped profiling 机制（§4.4）在实际评估中未测试，仅作为设计讨论存在。
- 缺少与 Mooncake（高带宽 RDMA 场景）的直接性能对比，无法判断 SmartGen 在高带宽场景下是否仍有优势或退化为 full transfer。

## Relations

- builds-on InfiniGen [37] [high]: SmartGen 直接采用 InfiniGen 的 KV selection 算法和 prefetch 技术作为其 on-demand 和 speculative transfer 的基础组件，§4.2–4.3 明确引用。
- orthogonal HACK [82] [high]: SmartGen 利用 KV sparsity 减少传输量，HACK 利用量化减少传输精度；论文 §6.3 明确指出二者可互补组合。
- extends Splitwise/DistServe [45, 85] [med]: 这些系统通过 layer placement 或 prefill-overlap 缓解传输瓶颈，SmartGen 在同一 P/D 分离架构下用选择性传输替代全量传输，解决它们未解决的带宽饱和问题。
- competes-with Mooncake [47] [med]: Mooncake 依赖高带宽 RDMA（800 Gbps）实现全量 KV 传输，SmartGen 面向低带宽云场景用选择性传输规避带宽瓶颈；二者目标场景不同但解决同一问题。

## Takeaway

- **方法可移植性高：** KV index/mask 抽象与具体 selection 算法解耦，三条传输路径的设计可适配 InfiniGen、HATA 等不同算法，工程集成成本低。
- **需重新检验的假设：** 位置相似性在 4K–16K 验证，但对超长上下文（100K+）或跨域分布偏移的鲁棒性未知；profiling 更新频率的工程开销未量化。
- **对比需谨慎：** SmartGen vs HACK 的对比混合了 sparsity 和 quantization 两个维度，若要评估传输策略本身的优劣需控制 KV 使用比例。
- **一句话记忆：** 不是传更少——而是分三级（预传重要 / 并行按需拉 / 闲时补齐），让网络传输永远不出现在 decoding 关键路径上。
